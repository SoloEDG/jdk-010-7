# LUMEN 光学实验室

二维几何光学的交互式实验台，支持自由探索与**多阶段隐藏答案课程**的制作、分发与独立试做。

安装依赖：`npm install`

本地启动：`npm run dev`

类型检查：`npm run typecheck`，生产构建：`npm run build`，测试：`npm test`。

Docker 启动：`docker compose up --build`，访问 http://localhost:18110 。

---

## 三种工作模式

| 模式 | 入口 | 能做什么 |
| --- | --- | --- |
| 自由实验台 | 默认 | 原有三个固定任务 + 任意搭建，器件库全部开放 |
| 教师 · 课程制作 | 顶栏「制作课程」 | 把当前场景定义为阶段，配置允许器件、解锁器件、提示与测量判定条件 |
| 教师 · 阶段预览 | 制作器内「进入预览」 | **只读**，可自由切换任意阶段，实时查看同一判定引擎的结论 |
| 学生 · 试做 | 教师侧「进入学生试做」 | 只看得到当前阶段，用真实光路结果提交，通过后解锁下一阶段 |

### 教师制作流程

1. 在自由实验台搭好第一阶段的初始布局，点击「制作课程」。
2. 编辑课程标题、阶段名称、任务说明与逐条提示。
3. 勾选本阶段**允许学生添加**的器件种类，以及完成后**解锁**的器件种类。
4. 添加测量判定条件：选择测量指标（接收能量占比、光斑 RMS 半径、命中光线数、光斑重心）、
   比较算子（≥ / ≤ / > / < / ≈ 容差）、目标值与目标接收屏。
5. 用「把当前布局存为本阶段初始布局」固化场景；用「+」继续新增阶段。
6. 制作器实时校验，错误阶段会标红并在下方列出全部问题。
7. 校验通过后「导出课程文件」，得到 `*.lumen-course.json`，可离线分发。

### 学生试做流程

- 步骤条只显示当前阶段，未来阶段显示为锁；器件库中未授权的种类带锁且不可点击。
- 调整光路后「提交测量结果」，判定完全在浏览器本地基于真实光路追迹完成。
- 通过后自动进入下一阶段，新阶段的初始布局与新解锁器件明确衔接。
- 提示按条解锁；工作布局自动保存，可随时关闭页面后继续。

### 阶段衔接规则

- 初始授权器件为 `光源` 与 `接收屏`。
- 阶段 *i* 可用种类 = 初始集合 ∪ 阶段 0..*i* 的全部 `unlocks`
  （本阶段声明解锁的器件在本阶段内即可用，否则学生无法完成解锁动作）。
- 某阶段解锁的器件必须出现在下一阶段的初始布局或允许列表中，否则导入校验报错。

## 课程文件与导入校验

课程是单个 JSON 文件（`fileType: "lumen-course"`, `version: 1`），包含全部阶段的布局、
授权、提示与判定条件。导入时执行**严格校验，收集全部错误而不是遇到第一个就中断**，
任何错误都会阻止课程载入并弹窗逐条展示，错误阶段绝不允许被悄悄跳过。校验覆盖：

- **缺失器件**：布局中出现不支持的器件类型、判定规则引用了布局里不存在的接收屏；
- **循环阶段**：阶段 id 重复、阶段关系图存在环；
- **损坏的判定条件**：未知指标/算子、目标值不是有限数值、`approx` 缺少容差、阶段没有任何规则；
- **衔接断裂**：布局或允许列表引用了尚未解锁的器件种类、解锁器件在下一阶段未出现。

## 撤销与授权

学生模式下，所有文档变更（增、删、改、撤销、重做、外部替换）都经过同一授权守卫
（`src/shared/guards.ts` 的 `documentUsesAllowedKinds`）。阶段切换会**清空撤销栈**，
即使历史栈被异常污染，守卫仍会兜底拦截——学生无法通过撤销退回包含未授权器件的状态。
教师预览是只读模式，实验台拖动、属性面板与删除按钮全部禁用，但可在任意阶段间自由跳转。

## 测量结论的一致性

教师预览与学生提交调用的是同一个纯函数 `evaluateStage`（`src/shared/grading.ts`），
输入同一份布局与同一份确定性光路追迹结果（`trace()`），因此两种模式必然得到一致结论。
单元测试 `teacher preview and student submission produce identical verdicts` 对此做了锁定。

## 进度的分别保存

- 学生进度按课程 id 分键存于 `localStorage`（`lumen-student-progress:<courseId>`），
  含已完成阶段、当前阶段、提示解锁数、各阶段提交快照与工作布局。
- 教师草稿使用独立键（`lumen-teacher-draft:<courseId>`），与学生进度互不覆盖。
- 自由实验台沿用原有的 `lumen-document` 键。

## 前端可保证的范围与边界（重要）

这是一个**纯前端、可离线运行**的方案，因此安全边界需要明确：

- **答案隐藏只能做到“界面不显示、进度不写入”**：判定条件、参考布局与课程同文件分发，
  主动打开 JSON 文件或浏览器开发者工具的人可以读到全部答案。前端无法对抗主动翻包。
- 若需要强保密（学生在任何情况下都接触不到答案/判定阈值），必须引入服务端判分：
  学生只上传测量结果或布局，由服务端持有的课程定义完成判定，前端只渲染结论。
- 可离线运行与可调试性的取舍：所有计算都在本机，无网络依赖、可随时断网使用；
  代价是上面的答案可见性，以及进度随浏览器数据清除而丢失。
- 判定本身是确定性的纯函数，不依赖随机数或时间，便于教师复现学生的任意一次提交
  （提交快照里保存了完整场景与每条规则的实测值）。

## 代码结构

```
src/shared/
  course.ts          课程/阶段/判定规则/学生进度的领域类型
  courseFactory.ts   建课、建阶段、复制阶段、解锁链推导
  courseIO.ts        序列化与严格导入校验（缺失器件/循环/损坏条件/衔接）
  grading.ts         教师与学生共用的确定性判定引擎
  guards.ts          器件授权纯函数（撤销栈同样受其约束）
src/features/course/
  model/useCourseSession.ts   自由/教师/学生三模式状态机
  lib/progress.ts             学生进度与教师草稿的分键持久化
  lib/files.ts                本地文件下载/选择（无网络依赖）
  ui/                         制作面板、学生面板、教师预览、受保护器件库
tests/
  physics.test.ts             原有光路物理测试
  course.test.ts              判定引擎与导入校验的单元测试
  integration.course.test.ts  jsdom 下真实 React 状态机的端到端工作流
  app.smoke.test.ts           <App/> 全模式挂载冒烟测试
```
